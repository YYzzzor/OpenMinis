# 任务归档

只处理当前任务或用户指定的 tasks/active/ 记录。没有持久任务记录的小工作无需补建记录来归档。遵循用户明确指令；本技能承接已有的自主归档授权，不另设审批。

## 判断

读取该任务的确认目标、验收证据、待办与阻塞，并按需核对当前成果。已达到确认的验收条件、必要验证及审核完成、没有待用户验收或后续动作时，可以归档。用户明确取消的任务也可归档，记录为取消而非完成。

归档前确认已按[Spec 写作与维护](../../../docs/harness/spec-authoring.md)同步受影响的长期规范及生成索引，或在任务中记录无须变更的具体理由。

有实质待办、证据不足或用户验收未完成时保留 active，简记原因和下一步。不要凭任务年龄、已提交、某个测试通过或审核无发现推断完成；不为归档额外运行无必要测试或启动审核。

## 执行与汇报

- 在记录中写明完成或取消状态、判断依据及日期。满足条件后直接归档，无需再等用户单独发出归档指令。
- 按[记录格式](../../../docs/harness/record-formats.md#生命周期与默认读取范围)移动到 tasks/archive/，保留原名：目录式任务整体移动；单文件任务连同同名 .checkpoint.json 移动。保留原始报告、附件和历史检查点字节，不覆盖已有同名归档。
- 更新维护中的入口链接，核对目标记录及附件存在、源位置已迁出。归档不等于删除、不隐含 Git 提交，也不归档 Codex 对话或 worktree。
- 简短汇报归档位置；未归档则说明具体待办，不重复询问已明确的授权。

本技能由 Agent 在相应阶段加载和执行，不是定时任务或 Hook。scripts/harness/task_state.py 只提供状态检查和检查点，不替代验收判断，也没有 archive 子命令。
