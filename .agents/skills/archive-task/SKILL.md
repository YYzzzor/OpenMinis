# 任务归档

## 可以归档的条件

- 验收清单全部打勾且有证据；或未完成项已写明原因，并经用户同意。
- 本任务新增或修改的 `[拟议]` 规则都已按 [update-spec](../update-spec/SKILL.md) 处理：完成的去掉标记；取消的删除新增规则、恢复修改规则的原文。并完成改后检查。
- 用户明确取消的任务也可归档，记为“取消”。

不要凭任务存在时间、已提交代码、某个测试通过或审查无发现来判断任务完成。

## 执行

1. 把状态行改为“完成”或“取消”，并写上日期；把“下一步”改为“遗留事项”，按实际情况列出未做的验证、已知限制和建议另开的任务，没有就写“无”。
2. 把任务目录整体移到 `tasks/archive/`，保留原名。旧式单文件任务连同同名的 `.checkpoint.json` 一起移动。
   - 移动后检查被 `.gitignore` 忽略的文件（如 `*.log`）：它们在原位置被强制跟踪过，到新路径后又会被忽略，提交时会被记成删除。用 `git status --ignored` 找出这些文件，暂存时用 `git add -f` 加入。
3. 用一句话汇报归档位置。条件不满足时保留在 active，说明缺什么。

归档不等于提交，也不删除任何证据。
