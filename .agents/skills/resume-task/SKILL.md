# 恢复任务

从用户指定记录开始；未指定时只列出 tasks/active/ 的任务标题和状态，选定后才读取相应正文，多个合理候选才询问。不递归扫描 tasks/ 或默认读取 tasks/archive/；active 无匹配时不自动回退到归档。读取目标、验收、决定（含否定方向）、下一步、阻塞与待审批事项。格式参考项目 docs/harness/record-formats.md。

在项目根运行 `python3 scripts/harness/task_state.py inspect <任务文件>`。若迁移项目没有脚本，使用只读 Git 命令核对分支、HEAD、暂存、未暂存、未跟踪文件和未完成 Git 操作。脚本仅核验状态，不能判断完成或自动修复。

记录过时时核实差异，不为符合记录覆盖代码、清理工作区或撤销修改。无检查点时据实际代码重建状态。待批准提案不是有效规则，只有明确用户批准才能改变审批状态。

简述恢复位置和下一行动后继续。有实质进展、决定变化、阻塞或交接时，主 Agent 更新任务，再运行 `python3 scripts/harness/task_state.py checkpoint <任务文件>`。完成恢复核对前不要覆盖旧检查点。实现与验收分别记录，不保证恢复运行进程或内部推理。

当前任务显著偏差自动纠正；影响后续任务的规则修改需先列明原因、具体修改和验证计划，等待用户审核。

归档只有在用户点名历史任务，或当前任务确实需要某份历史证据时才按具体路径读取；先说明用途，不连带加载邻近任务、审查轮次或附件。对归档任务显式运行 inspect/checkpoint 时须加 `--include-archive`。需要继续开发已归档任务时，先明确恢复意图，再移回 active 并更新状态；只读查询不改变归档状态。

任务验收完成或确认取消后，将记录及同名检查点、同目录附件一起移到 tasks/archive/，保留原名和原始审查证据。归档不是删除，不自动重写历史检查点来制造 match。

上述按需限制针对 Agent 的正文上下文。显式核验某个归档目录任务的检查点时，工具会读取该任务目录中未被 Git 忽略的附件计算摘要，但不读取其他归档任务，也不会把附件正文输出给 Agent。
