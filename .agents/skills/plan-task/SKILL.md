# 规划任务

1. **查事实**：读相关源码，从 [Spec 索引](../../../docs/specs/index.md) 选相关 Spec 整份阅读。代码或文档能回答的问题自己查。
2. **问取舍**：只问用户的意图和偏好，每轮少量问题。每个取舍先说明背景和各选项的效果，再给推荐及理由。
3. **写确认稿**：
   - 目标：完成后可观察的行为，以及明确不做的内容。
   - 方案：选择的路线及理由；有实质取舍时写出未采用的方案。
   - 图：涉及模块协作、数据流或状态变化时，用 Mermaid 画两张图，都标“拟议”：
     - 关系图：相关部分的职责和依赖；
     - 典型场景图：从一个用户操作开始，展示协作顺序，优先用时序图。
   - 验收：具体场景 → 预期结果 → 验证方式，引用 Spec 规则编号。
   - 执行边界：分支、设备、外部操作。新建分支或 worktree 需用户同意。
4. **用户确认后**：
   - 按 [update-spec](../update-spec/SKILL.md) 把新增或修改的规则写进 Spec，标 `[拟议]`。
   - 需要跨会话，或需要用户确认验收的较大任务，按 [任务模板](../../../tasks/TEMPLATE.md) 在 `tasks/active/` 建记录；一次会话能完成的小任务不建。

讨论或未回复都不算确认。实施中需要改变目标或验收时，先说明原因，再请用户确认。
