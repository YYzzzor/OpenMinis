# MinisX 图标设计

帮助用户通过讨论、看草图、比较方案和调参数来设计 MinisX 图标。无参考图的从零探索与已有图标的续作同样重要；根据本轮意图选择入口，不默认重画当前图标。用户预计只设计一两次，流程保持轻量，但允许为找到方向进行多轮提问和大量草图探索。

## 已知偏好与边界

- 用户喜欢 Anthropic / Claude 产品的设计风格，并表示当前有字、无字两版图标都以其为参考。默认延续温暖克制的配色、圆润而略不规则的轮廓、柔和明暗与细纹；这些是可调整的方向，不是要求复制 Claude 标识。
- 用户已认可原图并排对照、滑块调整、小尺寸预览、参数保存和导出的交互方式。第一版复现的细纹及立体感仍有差异，不能把对交互方式的认可视为最终图标验收。
- 主要方法为 JavaScript + SVG，Canvas 辅助生成纹理。Icon Composer 用于后续材质调整与外观确认；使用它不意味着必须增加强反光或透明玻璃效果。
- 本 skill 不额外要求创建任务、工作树、提交或审查轮次；遵循当前请求及执行目录实际适用的规则。上一次“不要创建任务”的指令仅属于那次复现，不永久代替后续用户指令。
- 独立设计稿的授权不自动包括替换应用资源、发布或上传。用户明确要求集成时再按项目流程执行，复用已有授权，不重复索要确认。

## 找到基准并续作

本节适用于用户希望复现或延续已有方案的情况。没有参考图或希望重新探索时，先使用下一节；不要把提供参考图设为开始设计的条件。

1. 从当前工作区定位 MinisX / OpenMinis 代码库，不硬编码本机目录。需要读取或修改该库时，先读适用的 `AGENTS.md`，核对实际状态；不要假定当前分支或已发布版本。
2. 确认用户本轮选择的有字/无字、浅色/深色基准，优先从对话和文件判断。读取图标配置确定被引用的文件，并实际查看图片；不要仅凭文件名选择。常用位置为 `src/ios/Assets.xcassets/AppIcon.appiconset/Contents.json` 及其他 AppIcon 资源目录。
3. 已有调参成果时，从当前对话和用户指定的交付目录定位该副本，在同一设计副本续作并保留用户参数。本 skill 内附初版模板；它是历史起点，不是用户最新设计的保证。
4. 需要复用调参界面时，把本 skill 的 [调参模板](assets/icon-studio/index.html) 及同目录所需文件复制到本轮可写的交付目录后再编辑。不要直接修改 skill 模板。模板参考图是 2026-09-27 的浅色无字版本，中央主体加 11 个外围形状，合计 12 个；它不包含有字版或深色版的几何与排版。复用交互机制不意味着必须复用这套构图。
5. 在 ChatGPT 项目镜像中工作时，`sources/` 为只读参考。缺少当前素材时说明所用历史基准；无法确定身份且会影响设计时再询问。

## 没有参考图时：提问、草图与收敛

- 从对话提取已知信息，用简短设计摘要区分已确认偏好和暂定假设。只询问会改变设计方向的缺失信息：图标要表达什么、期望给人的感受、是否使用字母或文字、必须保留或避免的元素、主要展示场景等；不让用户先掌握术语或给出精确参数。
- 可以进行多轮提问，但每轮集中在少数关键问题（通常 2–3 个），结合容易理解的选项或草图。不要一次抛出长问卷，也不要把“所有问题回答完”设为出草图的前提。在未回答内容不影响的范围内先画草图，明确暂定假设；需要用户决定的内容保持待定。
- 先探索不同的图形含义与构图，例如字母符号、抽象生长形态、聚合关系或单一主体；以项目含义和用户反馈选择方向。这些只是举例，不是每次必须完成的类别。Claude 风格偏好可指导气质，不限定图形必须沿用当前中央主体和外围元素。
- 用 JavaScript + SVG 快速制作成组草图。区别应体现在图形含义、轮廓、构图、数量或疏密等方面；不要仅换色、旋转或更换随机种子就称为全新方向。早期先用简洁的形状和有限颜色，避免为尚未选择的方向精修纹理和玻璃效果。
- 当方向确实不清楚时，允许生成大量草图，按方向分组、分批展示，并给每张稳定编号和一句简短说明。每批数量根据差异和可比较程度决定，例如先展示 6–12 张；这不是总数上限或必达数量。不以大量近似方案代替有意义的探索。
- 让用户指出喜欢的部分和不喜欢的部分，允许“都不喜欢”或“喜欢 A 的轮廓、B 的构图”。根据反馈归纳下一轮假设，不逼迫用户在不满意的候选中选一个；全部被否定时先调整设计含义或构图，再增加草图。
- 在同一交付目录保存候选编号、源文件、参数和简短的选择理由，避免覆盖仍在比较的方案；这是设计素材，不自动创建项目任务记录。提问已解决的问题不重复询问。
- 用户表达了偏好的方向后，逐步减少候选并进入轮廓、配色、纹理的参数化精修；选择方向不等于确认最终图标。停止条件是本轮设计目标得到回答或需要用户比较下一批草图，不未经请求无限生成，也不因为用得少而过早收敛。

## 重建与精修调参

- SVG 保存形状、路径、变换、配色和渐变。每个元素保留稳定 id、中文名称和独立参数；不要只交付一串难以修改的路径坐标。
- 将自然不规则的轮廓表达为少量有意义的控制项，例如突出程度、宽高、局部饱满度；无需把手绘感变成完全对称的几何形状。新增滑块必须真实对应渲染变量，不把单纯纵向缩放称为曲率控制。
- Canvas 只用于需要的颗粒、细纹等像素效果；固定随机种子，避免修改一个参数时其他纹理也随机变化。保持同一参数集的输出可重复。
- 原图用于对照、测量和配色参考。声称“代码复现”时，不得把原图嵌入 SVG、裁成图层或叠在输出上冒充重建；若用户明确选择保留原始位图素材，标明哪些图层沿用原图。
- 根据实际需求逐步开放参数。初版模板有主体大小、主体纵向比例、外围分布、外围形状大小、细纹、颗粒、明暗和冷暖。不要为了完整性一次塞入大量控件。
- 将用户的模糊反馈转成可检验的假设，例如“挤”先比较主体比例和间距，“太硬”先比较转角或轮廓。在方向已确定的精修阶段，每轮主要改变一个因素，提供可命名、可保存和可恢复的参数组合；这一约束不限制前期草图探索不同概念与构图。
- 先比较轮廓与布局，再结合渐变和纹理判断整体风格。纯色构图模式不能代替有质感的最终效果。
- 有字与无字版共用视觉参数，但分别调整构图、留白和文字位置；复现时实际查看有字版，不猜测字体或字样；从零设计时先明确要使用的文字，再比较字体或自绘字形方案。

## 页面与输出

有参考图时使用原图/设计并排；无参考图时改成按方向分组的草图比较，收敛后再用选定候选/调整版并排，不显示无关旧图或伪造参考图。保留小尺寸预览和保存方式。用户在页面改过的值优先保留；不覆盖浏览器存储或参数文件。换设计版本时使用不同的存储键，避免旧参数误套到新图形。

- 提供直接可看的预览、可编辑源文件、参数和本轮需要的 SVG/PNG。不要只给代码或技术报告。
- 完整 SVG 可以嵌入 Canvas 生成的纹理 PNG，但应说明它是混合素材；“纯矢量版”不得含位图。
- 模板中“只看轮廓”是纯色预览；“导出纯矢量版”仍保留渐变。圆角仅用于预览，不写入输出。
- 页面可直接在浏览器打开，无外部网络依赖。工具可用时主动展示交互页面；最终答复给预览图、可用链接和最主要差异。

## Icon Composer 衔接

仅当本轮涉及导入或交付时执行这一节。核对当前 Apple 文档及实际工具支持，不保证浏览器 SVG 特性能原样导入。

- 保持各图层相同画布和坐标（iPhone 的当前模板为 1024 × 1024），按需要拆分主体、外围形状和背景，不提前裁成应用圆角。
- 尽量以简单 SVG 传递可编辑形状；不支持的纹理或效果输出为对应透明 PNG 图层。需要文字的图层在适当阶段将文字转成轮廓。
- 图标固有纹理与系统动态高光、阴影分开处理，避免重复烘焙效果。简单背景可在 Icon Composer 中设置。
- 保留符合用户风格的材质强度，不自动将所有形状改成强玻璃质感。
- 浏览器预览、Icon Composer 导入和真机效果是不同证据；完成哪一层就报告哪一层。

## 适度验证

查看浏览器实际渲染。有基准时对照轮廓、位置、配色、纹理与小尺寸效果；从零探索时检查候选是否具有实际差异、是否符合已确认方向，以及缩小后是否仍清楚。对新增或修改的功能检查参数是否生效、恢复/保存是否正确、导出文件是否能打开。修改纹理逻辑时检查固定参数的可重复性。

模板源自已检查过的版本，不需要每次重新搭建测试框架；同一版没有新改动或疑点时不反复验证。记录实际发现的差异，不编造相似度评分，不将“文件成功生成”当作视觉验收。达到本轮设计目标后交付给用户选择，避免未经请求无限精修。
