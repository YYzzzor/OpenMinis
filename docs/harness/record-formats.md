# 记录格式草案

状态：提案 001 已批准，作为记录约定使用；示例不是当前任务的事实。可省略不适用字段，避免创建空附件。

## 任务命名

任务标题和文件名／目录名使用 `YY-mm-dd Name`：两位年、两位月、两位日，后接一个空格与简明任务名称。日期取任务创建日期，后续更新或归档不改日期。此约定经用户明确指定，见 [提案 005](proposals/005-task-naming.md)。

- 单文件：`tasks/active/26-09-11 修复会话恢复.md`。
- 有附件的任务：`tasks/active/26-09-11 实现 OpenMinis 开发 Harness/task.md`；内部 `task.md` 与附件名不重复日期。
- 归档保留同一名称，位置改为 `tasks/archive/`。完成或取消后即移入此目录，保留任务记录及其附件。

命令中的含空格路径使用引号；Markdown 链接目标使用 `<...>` 包围。已固定的历史审查材料不因当前任务更名而改写。

## 任务记录

```markdown
# <YY-mm-dd Name>
状态：planned / active / blocked / done / cancelled
更新：<时间>

## 恢复信息
分支：<实际分支>
最近核验 HEAD：<提交>
工作区：<暂存、未暂存、未跟踪及未完成 Git 操作>
下一步：<具体行动>
待审批：<提案链接及状态，没有则写无>

## 任务确认与执行边界
确认状态：待用户审阅 / 已确认 / 变更待确认 / 授权有争议
确认稿版本：<日期或版本，以及对话/文件定位>

设备与数据：<适用时列精确目标标识、允许影响的数据及启动前核对方法>
首轮验证与停止条件：<代表场景、观察方法、扩展前检查点；无新证据或范围改变时如何停止>

## 目标与验收
<用户确认的目标和范围>
- [ ] <可观察的验收条件>

## 上下文与决定
<代码与文档入口及用途、已确认决定、否定方向及理由>
<待验证假设明确标记>

## Spec 阅读清单
必读：<文档路径 :: 完整标题路径（或全文）；用途与必要的依赖小节>
按需参考：<文档路径 :: 完整标题路径；用途>
<不适用时省略；审查阶段绑定原文版本，委派时传递同一份清单>

## 实现计划
- [ ] <可独立检查的一项工作>

## 进展与验证
<实现情况，与验收是否通过分别记录>
<检查方法、结果、对应版本、环境及未检查范围>

## 阻塞与纠偏
<阻塞的解除条件；显著偏差事实和当前任务的修正>

## 审查
<请求、原始报告及处理记录的链接>
```

任务确认必须先于依赖该确认的执行，不能由任务状态、检查点或审查结论推断。小而明确的修改可引用用户直接指令，无需强制增加文档或重复审批。旧任务缺少上述字段时，恢复者核对实际对话依据后补充事实；无法核实时保持未确认，不批量追认历史任务。

## 每轮审查

有审查附件时，将任务升级为目录；每轮使用独立编号：`reviews/001-request.md`、`001-review.md`、`001-resolution.md`。请求引用快照清单，快照清单应包含代码和需求文件标识、Git 状态及排除范围；具体机器格式待脚本实现确定。

原始报告包含：请求编号、快照标识、审查工具/模型/版本、实际覆盖范围、总体结论、问题清单。总体结论区分阻断问题、非阻断问题、未发现问题和无法完成审查。

Spec 原文完整保留在快照中，必读小节与参考定位分别进入请求。报告的实际覆盖范围列出阅读的小节及补充内容；快照清单绑定原文摘要和选择范围。选择方式见 [Spec 上下文](spec-context.md)。

每个问题使用稳定标识 R1、R2 等，记录严重程度、对应要求、代码位置、触发条件、证据、是否待核实和建议验证。不要仅给数值评分或通过结论。

处理记录逐条记录状态（已修复/不采纳/待核实/待用户判断）、理由、改动版本及验证证据。后续复审链接到原问题，不覆盖原报告。

处理记录分别列明 Pi 的建议结论与主 Agent 的验收判断，后者依据已确认验收条件、核实结果和未解决事项；有分歧时记录具体证据与理由。Pi 的 blocking/no_findings 标签不能直接作为验收结果。

## 生命周期与默认读取范围

任务根目录为仓库根的 tasks/，与 docs/ 并列。active/ 保存 planned、active、blocked；archive/ 保存 done、cancelled。确定验收或取消后再归档，不能仅依据创建时间、是否已提交或一项审查结论推断完成。目录式记录整体移动；单文件式记录连同同名 .checkpoint.json 移动。保留文件名日期，修正维护中文档的链接；原始审查请求、报告、快照清单、证据和历史检查点保持原字节。

默认恢复只发现 active 的标题/状态，选定后读取该任务正文。archive 不参与被动搜索、正文加载、附件递归或背景收集。用户指定历史任务，或当前任务有明确的具体历史证据需求时，先说明原因，再仅取所需文件。查不到活跃任务时不自动回退到 archive。

归档时记录完成依据，更新有效入口链接；不对所有历史任务重新生成检查点。迁移导致检查点漂移是需要解释的事实，不代表应撤销当前代码。只有实际恢复并核实的任务才能重新建立当前检查点。
