# 提案 002：收窄指令范围，明确自主执行边界

状态：implemented（文档一致性已检查；长期行为效果待真实任务观察）。
日期：2026-09-11

## 原因和依据

用户要求结合 GPT-6 Astra 的官方指导审查 AGENTS.md。官方强调模型对技能与项目指令更敏感，模糊或冲突指令可能引起提前停止，并建议明确自主执行、表达、委派和验证范围。这是行为指导，不是新的 AGENTS.md 文件格式。

来源：[OpenAI GPT-6 Astra 行为指导](https://developers.openai.com/api/docs/guides/latest-model#gpt-6-astra-behavior)。以下是针对本项目的设计调整，不宣称官方要求每个项目采用相同条款。

## 审批

助手已在会话中逐项提出以下六项修改的原因与建议文本；用户回复「可以开始调整文档」，批准实施。本批准不包含实际 Harness 文件向 DeepSeek 外发的待授权请求。

## 具体变更

| 位置 | 原约定的问题 | 实施后的约定 |
| --- | --- | --- |
| AGENTS.md 教学部分 | 特性出现时就解释，触发范围过宽 | 仅在请求讲解、分析或学习时展开，普通实现和报告按需说明 |
| 新增 Task Execution | 缺少自主推进与澄清边界 | 已确认目标内自行处理可逆局部选择，必要时询问；受阻时继续独立工作，不重复请求已获规则审批 |
| Using CodeGraph | 无工具回退；同步警告限制读取范围 | 不可用或不足时直接阅读与搜索，有证据需要时复查，允许阅读其他必要文件 |
| Changes and Validation | 缺少验证停止条件 | 适当检查通过后，无新问题不重复或扩大；记录无法执行的检查 |
| Development Harness 委派 | 仅描述允许条件 | 可独立推进且收益超过交接成本时使用子 Agent，小任务或紧密上下文任务由主 Agent 完成 |
| Git Workflow | 分析分支要求被扩展为所有修改 | 分析注释使用 ios-annotated，其他开发遵循任务分支；不自动迁移或清理改动 |

对应措辞同步到 [设计文档](../design.md)。两项现有共享技能已检查：没有无条件教学、强制委派或重复审批规则，因此无需修改。提案 001 保留历史批准文本；当前实际规则以 AGENTS.md 为准。

## 保留的边界

跨会话记录、固定代码与需求审查、主 Agent 先检查再由 Pi 审查、原始报告保存、长期规则审批继续有效。自主执行不改变工具权限，也不把本次文档授权视为外部数据发送授权。

## 验证和撤销

检查六项调整与技能、设计的一致性，执行文档空白和本地链接检查。未改运行代码，不重复运行脚本测试或 iOS 构建。后续观察是否减少过度讲解、无谓澄清和重复验证；若出现遗漏必要审批或验收的实际案例，按同一审批流程提出局部修订。
