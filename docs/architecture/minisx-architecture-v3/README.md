# MinisX 架构导览 · 阅读版 v3

本版在第二版导航基础上，补充 iSH 命令执行、原生能力桥接和 iOS 系统框架，并增加独立原生能力清单。整体结构与发送消息流程继续保留。

## 文件入口

| 文件 | 打开后的阅读位置 |
| --- | --- |
| `index.html` | 整体架构 |
| `ish.html` | iSH 命令执行详解 |
| `native.html` | 原生能力桥接详解 |
| `ios-frameworks.html` | iOS 系统框架及能力对应表 |
| `native-capabilities.html` | 已接入原生能力、当前缺口与边界 |
| `message-lifecycle.html` | 发送消息，第 01 步 |

7 个入口都是自包含 HTML，携带同一套内容、样式和交互，可以单独保存。页面内的图文、筛选和导航使用内嵌资源；源码链接需要联网访问 GitHub。建议解压后先打开 `index.html`，或通过 `native-capabilities.html` 直接进入清单。

## 本版阅读路径

先阅读 **iSH 命令执行 → 原生能力桥接 → iOS 系统框架**。三个页面使用同一个“查看今天的日历事件”示例，把工具参数、shell 命令、原生处理器、系统 API 和返回结果串起来。

在任一模块中点击“打开完整清单”，可按以下四组浏览 27 组原生处理器注册：

| 阅读分组 | 条目数 | 范围 |
| --- | ---: | --- |
| 个人数据 | 6 | 日历、提醒事项、照片、健康、剪贴板、位置 |
| 系统与外部设备 | 9 | 闹钟、通知、家居、蓝牙、NFC、设备状态、地图、天气、URL 打开 |
| 媒体与内容处理 | 7 | 语音识别、朗读、播放器、FFmpeg、视觉分析、文本分析、音乐 |
| MinisX 应用内工具 | 5 | 内置浏览器、会话、应用配置、模型调用、诊断 |

每项并列展示常用读取/执行操作和当前缺口，展开后可查看授权条件、核查深度、注册位置与源码。关键词搜索同时覆盖能力名称、命令和限制。系统框架表也可以直接定位相应能力。

“缺口与边界”集中列出 11 类重点事项，分别标注“接口尚缺”“范围限制”和“待核验”。其他细项保留在各能力行内。这些分类描述固定版本的项目接入范围；实际授权、系统支持、硬件状态和运行结果仍需分别核对。周期性唤醒 Agent 并重新执行任务列为待核验。

文件、图片读取、记忆工具和 MCP CLI 在清单底部单列为相关入口，保持各自的实现路径和统计口径。

## 导航与整体关系

左侧主导航为整体架构、发送消息、原生能力清单、问题定位，以及版本与源码。窄屏时导航移到顶部。

整体图点击节点只选中并更新摘要；明确的详情链接进入模块页。详情页保留面包屑、全局位置缩略图、相邻模块关系和源码位置。iSH、原生桥接、iOS 框架有独立高亮位置。

从流程进入模块、再进入清单时，顶部保留原步骤的返回入口。从系统框架进入某项能力时，可以返回系统框架页；从能力条目进入模块后，可以返回原来展开的条目。浏览器前进、后退也可用于这些页面间的导航。


原有发送消息主流程保持 8 步，工具、失败、停止分别作为条件分支。25 个原有模块入口、MCP 阅读路径和 3 个问题定位示例继续可用。

本版沿用 v2 基线，补读协调执行、文件路由、原生注册、公共 JSON 输出、应用内权限，以及日历、天气等代表处理路径。27 组处理器的存在由 `ISHKernel.m` 注册入口核实；具体操作与缺口结合 `docs/specs/ios-device-data-capabilities.md`，并对部分处理器进一步阅读实现、授权入口或帮助文本。各项展开后单独标明本次阅读深度。

源码引用使用相对路径、关键符号和固定提交链接；代码行号只用于已掌握的范围。项目能力文档本身记录了其更早的核查基线，网页读取的是上述固定提交内的文档版本。网页没有执行这些命令，也没有访问真实手机数据。

旧 iSH 概述及少量源码注释仍描述串行队列；当前 `ISHExecutionCoordinator.execute()` 为独立进程准备管道和会话文件上下文，同会话与跨会话命令均有并发路径。文档保留这一差异与对应依据。

“已注册”证明入口存在；实际成功需要处理器覆盖操作、系统授权及运行条件同时满足。应用内工具权限、系统授权和命令参数条件分别解释。各处理器的完整安全审计、真实权限验证和设备执行结果属于进一步验证范围。

## 维护方式

```text
architecture-data.json      统一的模块、步骤、能力和源码引用数据
_source/template.html      页面骨架
_source/style.css          响应式样式
_source/app.js             图、路由、阅读层级、筛选和交互
_source/generate.py        自包含 HTML 生成器
_source/check_ui.py        可选的 Chromium 页面回归检查
validation.json            本次实际网页检查记录
CHANGELOG.md               版本变更说明
```

修改源数据或页面源文件后，用 Python 3 统一生成所有入口：

```sh
python3 _source/generate.py
node --check _source/app.js
```

生成器只依赖 Python 标准库，会检查节点、关系端点和能力数据的引用，再内嵌内容、CSS 和 JavaScript。保持 HTML 与源文件同步可便于后续放到项目的 `docs/architecture/` 下维护。

可选页面回归检查依赖 Python Playwright 与 Chromium。在具备这两项的环境运行：

```sh
python3 _source/check_ui.py
```

脚本自动查找系统 Chromium/Chrome；也可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定浏览器。它使用 `set_content` 载入 HTML，完成后更新 `validation.json`，测试时页面不调用模型或系统数据接口。
