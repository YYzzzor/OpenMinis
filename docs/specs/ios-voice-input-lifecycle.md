# MinisX iOS 语音输入生命周期

导航：[Spec 索引](index.md)；语音 Provider 的实例与模型组规则见 [iOS Provider 与模型路由](ios-provider-model-routing.md)；命令行 `apple-speech` 见 [iOS 设备能力](ios-device-data-capabilities.md)，与本文的聊天输入流程无关。

范围：聊天输入框中的语音输入，从授权、采集、识别到编辑和发送。

## 用户模型

- **U1** 语音输入是输入框的一种输入方式，不是“录完即发送”。识别文字持续写入同一份可编辑草稿；用户可以停止、等待收尾、用键盘修改、继续录音，最后用普通的发送动作提交。发送前草稿始终可见。
- **U2** 面板区分以下状态：等待、正在开启麦克风、采集中、识别或收尾中、可编辑结果、失败。
- **U3** `isBusyForComposer` 是编辑与发送的门禁：权限请求、最终音频派发、未完成的识别、重试或流式收尾尚未结束时，不能发送不完整的草稿。
- **U4** 语音面板正文使用 17 pt 基准字号，额外行间距为 4 pt；标题行与正文区域的布局间距为 -7.5 pt。正文使用面板现有可用宽度自然换行，默认字号的 iPhone 18 Pro 上约容纳 20 个中文字符；不插入强制换行、不横向平移、不缩小字号。正文最大基准高度为 160 pt，超出时滚动；字号和正文高度继续适配 Dynamic Type，标题和正文不得遮挡键盘按钮。

## 权限与启动

- **P1** 录音需要麦克风权限；使用系统 ASR 时还需要语音识别权限。
- **P2** 用户显式点击麦克风时可以请求授权；按上次输入模式自动进入语音时，只在权限已授予的情况下启动，不在冷启动时弹出授权。
- **P3** 权限被拒绝、没有可用的 ASR Provider、音频引擎启动失败是三种不同错误，各自给出可操作的提示。第三方 ASR 缺凭证不显示成“网络错误”。系统 ASR 的在线 / 离线选择受语言、设备和系统可用性限制。
- **P4** 重复点击不会启动第二套采集。离开聊天或切换到键盘时，未完成的启动请求失效、采集停止，已显示的草稿保留。

## 音频采集

- **A1** 一次录音只有一个 `VoiceActivityDetector` / audio engine 负责麦克风采集；流式 ASR 接收这一采集的 PCM，不另起第二套麦克风引擎做 VAD 或上传。
- **A2** 语音采集与回复朗读互斥：开始采集时停止或抑制 TTS，结束后才恢复。其他音频子系统通过 `AudioSessionCoordinator` 声明意图、按优先级切换，不永久占用 audio session。
- **A3** 资源护栏：无语音 30 秒自动停止；进入后台 15 秒后停止并收尾；单次连续采集最长 5 分钟（原始音频缓存上限同为 300 秒）。修改这些数值时同步更新界面文案、生命周期测试，并做真机资源验证。

## Provider 解析与切换

- **R1** 每次新的采集开始前重新解析 ASR 选择。第三方候选必须支持音频输入 / ASR、所属实例已启用、本设备有可用凭证。
- **R2** 显式选择 System、第三方配置不可用、系统识别不可用，三者对用户可区分；配置错误不显示成系统识别已成功。
- **R3** fallback 组按成员顺序尝试；load-balance 组在每次采集时重新生成 seed，轮换起始成员。
- **R4** 一个片段最多把候选链完整尝试一遍；只有当前成员失败才换下一个，不并发向多个 Provider 上传同一段音频。
- **R5** 某成员成功后，同一次采集的后续片段优先从这个 sticky 成员开始。

## 流式与分段识别

- **S1** 支持 `VoiceStreamingCapable` 的 Provider 产生 partial、final、finished、failed 事件；其他 Provider 在 VAD 停顿或用户停止后提交完整的 WAV 片段。
- **S2** partial 是当前片段的完整修订稿，可能变短或清空，整体替换而不是追加。
- **S3** final 固化当前片段并推进片段 id；空 final 同样推进，避免后续片段被阻塞。
- **S4** 分段请求可能乱序完成，正文按预留的顺序号依次释放；前一片段失败时以空结果解锁，后面成功的文字不丢失。
- **S5** 每轮流式录音有一个 generation。键盘编辑、重新录音、发送、离开页面或重置都会使旧 generation 失效，迟到的回调不能覆盖新的草稿。
- **S6** 流式失败时，已显示的 partial 保留并标为“未确认”，用户可以编辑或重试；没有识别出文字时提示“未识别到语音”，原有草稿不消失。

## 停止、编辑、继续与发送

- **K1** 用户停止时，先停止采集，再送出尾部音频，并等待所有排队中的识别完成；收尾期间保持 busy。
- **K2** VAD 从未判定为语音、但已有足够的原始音频时，尝试用原始音频识别，避免“说了话却没触发 VAD”而完全丢失。
- **K3** 切到键盘时，先完成或取消当前采集，再直接从 ViewModel 读取最终文字交给文本输入框，不依赖视图卸载的时序。
- **K4** 用户手动编辑期间，暂停把识别结果写入草稿；迟到的批量结果如果会覆盖编辑，就丢弃并明确提示，不静默改回机器文字。
- **K5** 继续录音以当前（可能已编辑的）草稿为基础，新识别的片段追加在后面。
- **K6** 发送时先使旧 generation 失效并重置语音状态；发送后迟到的 final 不能再填回输入框。
- **K7** 用户从键盘切到语音时，入口只在 `/` 菜单打开时取消菜单。普通输入不执行菜单取消逻辑。语音输入以保留下来的草稿为基础，新识别片段追加在原草稿后面；不说话立即返回、取消启动或识别失败都不得清空原草稿。
- **K8** 用户进入语音模式后，面板立即显示原键盘草稿。启动、采集和收尾期间，面板持续显示包含新增语音内容的完整草稿。

## 错误与重试

- **E1** 至少区分并持续显示最近一次失败：录音过短、未识别到语音、编辑期间结果被丢弃、麦克风权限被拒、语音识别权限被拒、没有可用 Provider、转写失败、启动失败。Toast 可以短暂提示，面板保留完整原因和手动重试入口。
- **E2** 自动重试只重用明确保存的片段音频，并受 generation 和取消状态约束；退出、发送或开始新录音后，旧的重试不能再修改文字。
- **E3** 错误日志不记录凭证。调试时保存原始音频属于高敏感诊断能力，仅限调试构建，并遵守保留期限和用户知情。

## 待决定

- [待决定] R2 的现状缺口：[VoiceProviderResolver](../../src/ios/Providers/Voice/VoiceProviderResolver.swift) 在显式 System、第三方组不存在或成员全被过滤时都可能返回空候选链；[VoiceInputPanel](../../src/ios/Views/Chat/Voice/VoiceInputPanel.swift) 遇到空链时直接使用系统识别，没有保留空链的原因。第三方配置失效时应报错、提示后回退还是自动回退，待决定。
- [待决定] 流式失败后，发送“未确认”的 partial 是否需要额外确认。目前允许保留并编辑。

## 验收场景

| 场景 | 期望 |
| --- | --- |
| 说话、停止、编辑、发送 | 停止后先显示收尾状态，最终片段到齐才可编辑和发送；发出的内容等于编辑稿；迟到的回调不改写已发送内容或空输入框（U3、K1、K6） |
| 已有文字、不说话立即返回 | 正式麦克风入口保留原草稿，返回键盘后文字和换行完整保留，继续输入接在原文字后（P4、K7） |
| 已有文字后语音追加 | 原文字立即显示，partial 只修订当前语音片段，最终文字包含原草稿和新增语音，返回键盘后仍完整（S2、S3、K5、K7、K8） |
| 多行填满语音正文 | 采用已确认的 4 pt 额外行间距、-7.5 pt 标题行间距和完整可用宽度；正文溢出时滚动，Dynamic Type 和键盘按钮保持可用（U4） |
| 两个分段乱序返回 | 第二段先到时缓存，第一段完成或失败后按顺序释放；文字不倒序，第一段失败也不丢第二段（S4） |
| 流式中间结果反复修订 | 较短的 partial 替换较长的；final 只固化一次；同一或更早片段的迟到 partial / final 被忽略（S2、S3、S5） |
| 切换键盘或离开页面 | 待启动的权限任务和采集被取消，草稿保留；旧回调失效；不会在后台重新开麦（P4、S5） |
| 首选云 ASR 不可用 | 按顺序只尝试可用成员，同一片段不并发上传；成功者成为 sticky 起点；全部失败时显示可理解的原因，保留草稿和可重试的音频（R3–R5、E1） |
| 候选链过滤后为空 | 按“待决定”中的现状走系统识别，并受系统权限和可用性限制；不视为用户选择了 System，也不提前判定成功（R2） |
