# 资源开销与性能审查规范

导航：[Spec 索引](index.md)。

范围：所有功能在规划、实现、修复、重构、调试、测试与审查各阶段的资源开销要求。依据：维护者 2026-09-28 要求“不论什么时候，将资源开销控制在合理的范围内都是必须遵守的事情，在审查时要重点关注”。

## 原则

- **R1** 在满足正确性、体验与可靠性的前提下，CPU、GPU、内存、能耗、网络、磁盘和后台执行开销与实际用途相称。原型、临时实现或“功能已正确”都不能成为保留明显浪费的理由。
- **R2** 降低开销不能以丢失数据、降低识别正确性或破坏交互为代价。
- **R3** 优先消除无效工作、缩小更新范围、复用必要结果；提高采样率、刷新率、并发数、缓存容量或重复执行不是默认方案。
- **R4** 优化也要有必要性：不为理论收益引入复杂度、持续监测、额外服务或工具链。验证与改动风险相称，文案类修改无需性能采样。

## 实现要求

- **I1 高频路径**：控制更新频率和影响范围，局部数据变化只刷新相关部分；采集、识别、展示可以采用不同频率。动画平滑用局部过渡，而不是提高全链路频率。
- **I2 生命周期**：定时器、动画、订阅、音视频采集、异步任务和后台作业都有明确的启动、停止、取消与释放条件。需求结束即停止；不可见、暂停或后台时按真实需要降频或停止，用户明确需要持续执行的任务继续运行。
- **I3 有界资源**：缓存、音频缓冲、队列、重试、并发与日志都有容量、时限、清理或退避策略；不出现积压、无限增长、重复请求、忙等、无意义轮询和高频落盘。
- **I4 关键线程**：主线程和实时音频回调中只做必要工作，不做阻塞、多余的分配、复制和重计算。把工作挪到其他线程不能代替减少总开销，也不能引入无界任务或竞态。
- **I5 可检查的边界**：新增的持续、高频或随输入增长的工作，要说明必要性及可检查的边界（如刷新上限、缓存容量、队列长度、停止条件），数值按使用场景和设备确定。

## 审查

- **V1** 本规范是每轮主会话自查和独立审查的必读材料；资源开销是固定审查项。
- **V2** 审查至少回答与本次改动相关的五个问题：
  1. 新增或扩大了哪些持续工作、计算、分配、复制、渲染、请求或 I/O，是否必要，边界是否合理；
  2. 更新是否局部、按需，有无重复计算、无效刷新、轮询、忙等或无界增长；
  3. 暂停、取消、离场、后台、异常和重试时，资源能否正确停止或释放，需要持续运行的功能是否保持正确；
  4. 代表性用户路径下有无卡顿、变慢、能耗或内存增长风险，现有证据能否支持结论；
  5. 优化是否损害正确性、体验、可维护性，或只是把成本转移到别的线程、阶段或资源。
- **V3** 审查结论单独列出资源影响、判断依据、已验证与未验证范围。没有运行时资源影响的改动写明“不适用”及理由，不为凑数制造优化项。
- **V4** 与本次改动相关、已确认且不必要的浪费，处理并验证后才能把相关要求记为完成；范围外的问题单独记录，不擅自扩大修改。

## 证据

- **E1** 静态阅读可以确认实现事实（如无界队列、未取消的任务、重复计算），但不能代替真机上的 CPU、GPU、内存、能耗或流畅度测量。
- **E2** 高风险或仍有实质疑点时，用最小的代表性路径补充运行证据；前后对比记录设备、构建配置、输入与场景。模拟器或演示效果不能证明真机性能。
- **E3** 已确认的问题与待验证的风险分开写；未测量的指标记为未验证。“看起来流畅”、构建成功或审查无发现都不等于资源开销已通过。验证结果记录在任务中。

## 验收场景

| 场景 | 验收条件 |
| --- | --- |
| 新增持续任务、动画、采集或订阅 | 写明启动与停止条件；检查需求结束后的取消、释放及必要的后台行为（I2）。 |
| 队列、日志或重复请求随输入增长 | 给出与用途相称的容量或停止边界；用代表性输入验证没有无界积压和无效重复工作（I3、I5）。 |
| 只改文档或规范 | 写明无产品运行时影响，不做真机性能采样；使用的工具本身扫描与输出仍应有界（R4、V3）。 |
