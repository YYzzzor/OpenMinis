# 资源开销与性能审查规范

导航：[Spec 索引](index.md)；章节目录由[上下文工具](../harness/spec-context.md#受控阅读入口)从本文标题生成，不另手写目录。

本文件是已确认的跨功能规范；下列场景用于选择验证，不代表所有功能已经通过性能测量。

状态：已确认的项目级要求。依据：维护者在 2026-09-28 明确要求“不论什么时候，将资源开销控制在合理的范围内都是必须遵守的事情，在审查时要重点关注”。

## 适用范围与原则

- 控制资源开销是持续约束，适用于所有功能及规划、实现、修复、重构、演示、调试、测试与审查阶段，不限于语音或动画。不能以原型、临时实现或功能正确为由忽略明显浪费。
- 在满足正确性、体验与可靠性的前提下，将 CPU、GPU、内存、能耗、网络、磁盘和后台执行开销控制在与实际用途相称的范围。合理不等于零开销，也不等于一律追求最低开销；不得通过丢失数据、降低识别正确性或破坏交互来减少资源使用。
- 不把更高采样率、刷新率、并发数、缓存容量或重复执行当作默认解决方案。优先消除无效工作、缩小更新范围、复用必要结果，并使资源生命周期与实际需求一致。
- 优化本身也必须有必要性。不得为了理论收益引入收益不明的复杂度、持续监测、重复测试、额外服务或工具链。验证与改动风险相称，不要求每次文案修改都做性能采样。

## 实现要求

- 高频路径：控制更新频率和影响范围，避免局部数据变化引发整页刷新、重复布局、重复解码或无关计算；采集、识别、展示不必采用相同频率。动画平滑应使用适当的局部过渡，不能只靠提高全链路频率解决。
- 生命周期：为定时器、动画、订阅、音视频采集、异步任务和后台作业明确启动、停止、取消与释放条件。需求结束后停止无效工作；不可见、暂停或后台状态按真实功能需要降频或停止，不得误停用户明确需要持续执行的任务。
- 有界资源：缓存、音频缓冲、队列、重试、并发与日志应有适当的容量、时限、清理或退避策略。避免积压、无限增长、重复请求、忙等、无意义轮询和高频落盘。
- 关键线程：避免在主线程或实时音频回调中执行不必要的阻塞、分配、复制和重计算；将工作移到其他线程不能代替减少总开销，也不能引入无界任务或竞态。
- 实际边界：对新增的持续、高频或可能随输入规模增长的工作，说明必要性及可检查的资源边界，例如刷新上限、缓存容量、队列长度或停止条件。按使用场景与设备确定，不能套用没有依据的统一数字。

## 审查重点与证据

本规范是每轮主 Agent 自查和独立审查的必读材料。资源开销是明确审查项，不能仅在用户报告卡顿、耗电或内存问题之后才关注。

审查至少判断与本次改动相关的以下事项：

1. 新增或扩大了哪些持续工作、计算、分配、复制、渲染、请求或 I/O；它们是否必要，开销边界是否合理。
2. 更新是否局部且按需；有无重复计算、无效刷新、轮询、忙等或无界增长。
3. 暂停、取消、离场、后台、异常和重试时，资源能否正确停止或释放；需要持续运行的功能能否保持正确。
4. 代表性用户路径下，是否引入卡顿、响应变慢、能耗或内存增长风险；所提供的证据能否支持结论。
5. 优化是否损害正确性、体验、可维护性，或把成本转移到了另一线程、另一个阶段或另一项资源而没有减少浪费。

审查记录应明确列出资源影响、判断依据、已做验证与未验证范围。没有运行时资源影响的修改可以注明“不适用”并简述理由；不得机械制造优化项。

静态阅读可以确认无界队列、未取消任务、重复计算等实现事实，但不能替代真机 CPU、GPU、内存、能耗或流畅度测量。高风险或仍有实质疑点时，采用最小的代表性路径补充运行证据；比较前后结果应记录设备、构建配置、输入与场景。演示或模拟器效果不能直接证明真机性能。

区分已确认问题与待验证风险。未测量的指标如实记为未验证，不能用“看起来流畅”、构建成功或审查无发现宣称资源开销已通过。发现与当前改动相关、已确认且不必要的资源浪费时，应处理并验证后再将相关要求记为完成；范围外问题单独记录，不擅自扩大修改。

## 维护验收场景

| 场景 | 验收条件与证据 |
| --- | --- |
| 新增持续任务、动画、采集或订阅 | 说明启动与停止条件，检查需求结束后的取消、释放及必要后台行为。 |
| 队列、日志或重复请求随输入增长 | 给出与用途相称的容量或停止边界；用代表输入验证无无界积压及无效重复工作。 |
| 只调整文档或规范路由 | 说明无产品运行时影响，不机械要求真机性能采样；工具本身的扫描与输出仍应有界。 |

[Spec 写作与维护](../harness/spec-authoring.md)说明如何在任务中记录验证结果，避免把静态检查写成实测结论。
