# iOS Agent Run Lifecycle

导航：[Spec 索引](index.md)。

范围：一次会话回合如何开始、推进、持久化、中断和恢复，包括发送、编辑重发、流式显示、工具调用、Stop、Retry、Resume、上下文 offload 与压缩、后台恢复、会话删除。Provider 的传输细节与模型路由见 [Provider 与模型路由](ios-provider-model-routing.md)。

```text
草稿 / 附件
  → 发送前校验与上下文检查
  → 建立或载入会话，持久化用户消息
  → Provider 流式响应
  → 零个或多个工具批次与后续模型轮次
  → 正常完成 / 错误 / 用户停止 / 上下文耗尽 / 轮次上限
  → Retry、Resume 或从历史用户消息重跑
```

- **O1** 界面消息、Provider history、数据库记录是三种相关但不同的表示。任何编辑、重试、压缩都要保持三者的顺序和边界一致，不只修改屏幕显示。

## 发送

- **S1** `send()` 在以下情况不开始新回合：远端只读会话；文本和已就绪附件都为空；当前正在处理。未完成或失败的附件从待发送集合中剔除；输入模式等“已使用”偏好在真正发送时才提交。
- **S2** 开始前依次：编辑重发时使旧的上下文用量失效；检查上下文策略；清除旧的流式和运行中工具状态；清空输入框并建立用户消息；确保会话、kernel 和后台处理可用；拿到会话的并发槽位后才进入 Agent 循环。
- **S3** 编辑已有的用户消息后发送，会截断它及之后的界面、history 和持久化消息，再以编辑后的消息继续。界面要让用户明白这会丢弃后续分支。

## 上下文检查与压缩

| 模型上下文窗口 | 自动 offload | 自动压缩 | 达到上限 |
| --- | --- | --- | --- |
| `<32K` | 无 | 无 | 约 90% 时耗尽 |
| `32K–<64K` | 剩余约 10K 时 | 无 | 到 offload 阈值即耗尽 |
| `64K–<128K` | 剩余约 20K 时 | 剩余约 10K 时 | 走压缩 |
| `>=128K` | 剩余约 40K 时 | 剩余约 20K 时 | 走压缩 |

- **C1** 发送前需要压缩时：Shortcut 会话或开启了自动压缩的会话直接执行；其他交互会话先提示用户。
- **C2** 上下文耗尽时：Shortcut 会话产生内联错误；交互会话提示新建会话或清空。
- **C3** Agent 循环每一轮都重新检查：先 offload 大的工具内容，再决定循环内压缩，或停在可恢复的状态。单个用户回合最多自动压缩 3 次。修改阈值或次数时同步更新测试和用户提示。
- **C4** 压缩用摘要替换较早的有效 history，并持久化压缩标记；界面可以保留灰化的历史和分隔线。压缩不等于删除原记录，也不能破坏工具调用与结果的配对。

## 流式响应与工具循环

- **L1** 每轮 Agent 循环先解析当前 Provider 和可用工具；没有模型配置时显示错误并结束。
- **L2** 流式内容写入同一条 assistant 消息；已提交的块与未提交的流式尾部可以区分。
- **L3** 模型返回工具调用时，工具结果以匹配的 id 写回 history，再发起下一轮请求。
- **L4** 同一批工具可以并发执行，完成顺序不等于声明顺序；写回模型和界面时恢复确定的对应关系。
- **L5** `ToolLoopDetector` 识别重复循环；另有每个用户回合最多 200 轮 Agent 循环的硬上限。达到上限时给出用户可见、可恢复的停止状态。
- **L6** 工具结果之后模型返回空响应时，带提醒重试一次；仍为空则明确失败，不静默结束，也不无限重试。
- **L7** Provider 自动重试或模型组 fallback 只清除未提交的流式尾部，不抹掉已提交、已持久化的块。

## 持久化与重建

- **P1** 新草稿在首次发送时才建立会话，再写入消息。
- **P2** 消息按 `sort_order ASC, created_at ASC, id ASC` 读取，顺序确定。
- **P3** 错误信息是设备本地字段；Retry 清除内存中的错误时，同时清除持久化的错误，避免重新加载后旧提示再次出现。
- **P4** 工具调用与结果、流中断次数、模型与 Provider 标识、压缩标记，足以在重新加载后重建可见状态和有效的 Provider history。
- **P5** 同步或重新加载可能替换界面消息实例；运行中的循环用稳定的 id 重新定位目标 assistant 消息，不长期持有可能失效的数组下标。
- **P6** 孤立的工具结果被移除；孤立的工具调用补上明确的失败占位，避免下一次请求因协议不完整而失败。

## Stop

- **T1** 用户按 Stop 时，界面立即退出处理中状态，并：取消并发槽位的等待和当前任务；终止该会话的 shell 进程；唤醒前台等待和浏览器接管的等待，使取消能够传播；停止自动重试倒计时和后台处理；把未完成的工具转为可理解的中断状态，适用时提供 Resume。
- **T2** Stop 不删除已提交的文本和终端结果，也不撤销工具已产生的外部副作用。排队中的 prompt 与被停止的当前回合不混成同一条响应（排队语义见“待决定”）。

## Retry、Resume 与历史重跑

- **R1** `retry()` 只在未处理中、且最后一条是 assistant 消息时开始。它保留已完成的工具块和对话历史，清除失败回合未提交的流式尾部、旧错误和孤立结果，然后从最后的提交边界继续，而不是从头重发整段会话。
- **R2** `resume()` 要求 `canResume` 且未处理中：
  - 末尾是部分完成的 assistant 消息：保留已提交内容，清除未提交的尾部；history 以 assistant 结尾时，注入一条仅供模型理解的 Continue 提醒，然后继续同一条 assistant 消息；
  - 末尾只有已持久化的用户消息、还没有 assistant 消息：从该用户消息重新请求回答，不假装存在部分回复。
- **R3** `retryFromMessage` 保留选中的用户消息，截断其后的界面、Provider history 和数据库记录，再运行新的分支；替换附件时同步更新对应的 history 和展示信息。界面和 history 中找不到安全锚点时，宁可保留更多历史，也不误删大段会话。

## 会话删除

- **D1** 删除会话时，先排队云端的会话及子记录删除，再删除本地消息、压缩标记和媒体，并写入保留 30 天的近期删除标记，防止删除传播完成前旧的云记录让会话复活。
- **D2** 删除是数据生命周期行为，不等于从列表隐藏；同时停止该会话的活动，清理角标、Live Activity、缓存和文件路由。

## 发现信息与背景知识

- **B1** Agent 循环开始和 fallback 重建时，组装 Skill / MCP 的发现信息，以及受 `memoryEnabled` 控制的 GLOBAL 和近期日志；SOUL 身份部分不受该开关控制。发现列表不代表正文已读取、MCP 工具已执行或模型已遵守。
- **B2** 开关切换、消息截断、清空会话、Retry 都不是全局数据删除，也不撤销已发生的副作用。具体范围见 [Skill](ios-skills-lifecycle.md)、[MCP](ios-mcp-integrations.md)、[Memory](ios-memory-lifecycle.md)；费用在消息之外单独记账，见 [用量与费用](ios-usage-cost-and-balance.md#账本规则)。

## 待决定

- [待决定] Stop 之后排队中的 prompt 是继续执行还是全部取消。目前的实现包含继续执行排队的路径（T2）。

## 验收场景

| 场景 | 期望 |
| --- | --- |
| 正常的文本加工具回合 | 用户消息先持久化；assistant 流式显示；工具调用与结果 id 配对；重新加载后文本和工具块顺序一致；结束后处理中和后台状态清零（P1、L2–L4） |
| 工具运行中按 Stop，再 Resume | 该会话所有 shell 进程被终止；已提交的文本和终端结果保留；运行中的块显示中断而不是一直加载；Resume 不重复已完成工具的副作用，继续同一条 assistant 消息（T1、T2、R2） |
| 出错后 Retry | 旧错误提示在内存和数据库中都被清除；已完成的工具结果保留；只丢弃未提交的流式尾部；重新加载后不再出现已清除的错误（R1、P3） |
| 从旧的用户消息重跑 | 选中的用户消息保留，之后的分支在界面、history、数据库中一致删除；新附件替换正确；同步重新加载不会恢复旧分支（R3、P5） |
| 上下文接近上限 | 按窗口大小选择 offload、压缩或耗尽；非自动压缩的交互会话先提示；单回合不超过 3 次循环内压缩和 200 轮上限；达到上限时有可见的恢复入口（C1–C3、L5） |
| 用户消息写入后 App 被系统回收 | 重新加载后识别出“末尾只有用户消息”并提供恢复；恢复从该用户消息请求，不插入伪造的部分回复（R2） |
