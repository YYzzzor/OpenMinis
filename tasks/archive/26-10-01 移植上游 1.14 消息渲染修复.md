# 26-10-01 移植上游 1.14 消息渲染修复

状态：完成（2026-10-01）　｜　Spec：无（纯渲染修复，不新增行为规则）

## 目标

从官方 OpenMinis 1.14（tag `1.14`）只移植 App Store 更新说明中“修复消息内容渲染问题”对应的 iOS 改动，用户可观察到：

1. 行内代码不再丢失背景：流式输出时，含 `|` 的普通句子里的 `` `code` `` 不再先显示为纯文本、行结束后才变成代码底色。
2. 行内代码对齐：列表内换行的代码底色从文字缩进处开始；跨行代码底色上下连成一块；标题里的行内代码随标题字号缩放并垂直居中。
3. 带编号的公式（`\tag`、`align` 自动编号）编号不再压在公式上。
4. 内容完全显示的代码块不再出现滚动条、不回弹，拖动消息列表经过代码块时不再“卡住”。

不做：1.14 中的图片/视频占位探测、复制菜单重组、渲染器缓存上限、状态栏点击回顶（代码块 `scrollsToTop`）、KaTeX 像素探针越界修复、Standalone 镜像测试。

## 方案

在 `main` 上按改动块（hunk）挑选 `git diff 1.13 1.14`，上游注释原样保留（标签 `[T-…]`），便于以后整体升级 1.14 时这些块直接对齐。三个文件在 MinisX 中自 1.13 起未改动，补丁干净应用。

- `src/ios/Views/Chat/MarkdownPrepRegex.swift`：`splitStreamingTableTail` 只在行首为 `|` 时走纯文本（T-ios-inline-code-streaming-flicker）。
- `src/ios/Views/Chat/SelectableMarkdownView.swift`：行内代码字号随上下文（T-md-inline-code-context-font）；底色左缘对齐缩进（T-ios-inline-code-list-indent）；跨行底色拼接（T-ios-inline-code-wrap-gap）；代码块按轴开关滚动条/回弹/滚动（T-codeblock-hide-idle-scrollbars、T-codeblock-offset-reset）及外层手势让渡判断。
- 行内代码 MinisX 自行调整：① 上游 x-height `.baselineOffset` 照常移植（曾误判它导致黑色 `/`：对照实验被“重启后从数据库重新渲染”干扰，已撤回）；② 首尾留白改用上下文字体并以字距撑开（Menlo 等宽，U+200A 在其中宽 8.67pt，首部看起来像多了一个空格；1.13 已存在）；首部改用不可断行的 U+202F，避免代码换到行首时留白留在上一行；复制/朗读路径同步去掉 U+202F；③ `inlineCodeTrailingInset` 2→3，折行续行左侧补同样内边距（按 x ≥ 0 截断）。用户要求代码与底色边缘留一点空。
- 流式淡入修复（1.13 起存在，上游 1.14 未修）：流式中字符串仍是追加、但属性重排而走整体替换时（如闭合反引号把 `` `/ `` 变成代码），`TextFadeAnimator` 未取消，逐帧把旧前景色写回新内容同一位置，`/var` 的 `/` 变黑且脱离底色。整体替换前调用 `fadeAnimator.cancelAll()`。证据：同一条回复流式结束后 `/` 为黑，重启重新渲染后为橙。
- 代码块配色改为 One Dark 底色 `#282C34`、文字 `#ABB2BF`，浅色/深色模式一致（`codeBlockBackground` / `codeBlockTextColor`，用户亲手修改）。不做语法着色。
- `src/ios/Resources/KaTeX/katex-render.html`：有编号时给公式行留出右侧编号槽（T-ios-latex-tag-overlap）。保留以对齐上游，但 iOS 聊天公式实际走原生 SwiftMath，不经过此页面，对聊天无效。
- `src/ios/Agent/Markdown/SwiftMathRenderer.swift`（MinisX 自行修复，上游 1.14 未覆盖）：SwiftMath 不支持 `\tag`，整条公式报 `Invalid command \tag` 后降级为系统字体 Unicode 文本，显示为 “E = mc² 1”。新增 `rewriteEquationTags`，在 SwiftMath 与降级路径前把 `\tag{X}` 改写为 `\qquad\text{(X)}`、`\tag*{X}` 为 `\qquad\text{X}`，去掉 `\notag`/`\nonumber`。编号不右对齐。
