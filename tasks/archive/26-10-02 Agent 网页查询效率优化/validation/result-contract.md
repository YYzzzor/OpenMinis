# web_read 模型结果契约

维护者已于2026-10-02确认采用小型 JSON，正文保留 Markdown。
本文件规定第一版的结果格式；首版代码已接入并取得定向测试证据，整体验收尚未完成。
行为依据为 [Spec](../../../../docs/specs/ios-web-read.md) 的 C1–C4、F3 和 I3。

## 模型收到什么

每次可提交的工具结果是一个 JSON 对象。
应用将对象序列化为字符串，再由 Provider 包装原工具协议。
Provider 保留原调用标识，不在正文中另造工具调用。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `url` | 字符串 | 正文或资源的实际来源；未取得响应时使用请求网址。 |
| `title` | 字符串或 null | 已取得的页面标题；没有可靠标题时使用 null。 |
| `retrieved_at` | 字符串或 null | 取得来源响应的 UTC 时间，采用 ISO 8601；没有响应时使用 null。 |
| `read_status` | 字符串 | 按下表说明本次读取状态。 |
| `content` | 字符串 | 模型需要的 Markdown 正文；没有可读正文时为空字符串。 |
| `limitations` | 字符串数组 | 已知的缺失、截断、认证或失败原因；没有已知限制时为空数组。 |

下列字段只在相关情况出现时提供。

| 字段 | 提供条件与含义 |
| --- | --- |
| `requested_url` | 请求网址与实际来源不同时提供，说明跳转或来源替换。 |
| `source_note` | 使用备用正文时提供，说明其与原页面的关系及覆盖限制。 |
| `document_id` | 已保存正文时提供；编号受原聊天、当前用户请求和原身份约束。 |
| `continuation` | 已保存正文的片段需要定位或续读时提供，含返回范围和保存边界。 |
| `locate_status` | 执行定位时提供，区分命中、已保存范围内未命中和目标尚未覆盖。 |
| `resources` | 发现与目标有关的未读取资源时提供地址、类型和未读取状态。 |
| `offloaded_result_file` | 结果已转存时提供完整原 JSON 的文件地址；模型通过 `file_read` 读取。 |

`resources` 每项使用 `url`、`type` 和 `read_status: "not_read"`。
需要说明资源与正文的关系时，该项增加 `context`。
工具不把全部装饰图片和链接加入结果。
响应格式冲突只在影响读取或交接时写入 `limitations`。

### 读取状态

| `read_status` | 含义 |
| --- | --- |
| `text_ready` | 本次返回的正文可读，工具未发现读取缺口。 |
| `partial` | 正文部分可读，或返回片段之外仍有内容。 |
| `resource_only` | 工具只返回资源信息，尚未读取其内容。 |
| `restricted` | 认证、交互、访问或资源条件阻止继续读取。 |
| `failed` | 工具因网络、解析或其他错误未完成读取。 |
| `cancelled` | 调用已取消；已删除会话不因提交结果而恢复。 |

这些状态说明工具读取事实，不表示模型已经完整回答用户问题。
工具返回部分正文后超时，使用 `partial` 并在 `limitations` 说明超时。
没有正文且超时，使用 `failed` 并说明原因。
请求、批次或会话已停止时，应用按原生命周期决定是否保留取消记录。
迟到回调不能补交正文或把取消状态改为成功。

### 正文范围和定位

`continuation` 使用以下整数位置：

| 字段 | 含义 |
| --- | --- |
| `start`、`end` | 本次返回片段在固定正文中的起止位置，包含起点、不包含终点。 |
| `saved_end` | 从位置0连续保存到此处的正文边界。 |
| `next_offset` | 尚有已保存后续内容时提供的下一次读取位置。 |

编号续读沿用原来源和抓取时间，不把缓存读取时间作为重新抓取时间。
位置按固定正文的 Unicode 码点计数，不使用原 HTML 或字节偏移。
续读返回连续片段，`end` 不超过 `saved_end`。
已保存正文之外的缺口写入 `limitations`，不能据此承诺续读。
`next_offset` 只在已保存范围内提供；它不承诺尚未下载的内容。

`locate_status` 分别使用以下值：

- `found`：工具已返回命中的正文片段。
- `not_found_in_saved_content`：工具在已保存范围中没有找到目标。
- `not_covered`：工具尚未取得完成目标定位所需的正文覆盖。

未命中不等于整个网页不存在目标。
正文不完整且已保存范围未命中时，工具使用 `not_covered`。
工具同时在 `limitations` 说明：未取得部分是否包含目标尚不能判断。
这个状态不表示工具已经证明目标存在于缺失部分。

### 示例

以下示例中的地址和正文均为说明用途。

```json
{
  "url": "https://example.com/pricing",
  "title": "价格说明",
  "retrieved_at": "2026-10-02T01:00:00Z",
  "read_status": "partial",
  "content": "# 价格说明\n已取得的正文……",
  "limitations": ["页面仍显示价格表加载提示。"],
  "document_id": "doc_1"
}
```

```json
{
  "url": "https://example.com/manual.pdf",
  "title": null,
  "retrieved_at": "2026-10-02T01:00:00Z",
  "read_status": "resource_only",
  "content": "",
  "limitations": ["本工具尚未读取 PDF 内容。"],
  "resources": [{"url": "https://example.com/manual.pdf", "type": "application/pdf", "read_status": "not_read"}]
}
```

## 应用保留什么诊断

详细阶段耗时、资源计数和内部请求时序保留在诊断记录中。
诊断按原聊天、用户请求及工具调用关联，不逐项送入模型上下文。

| 诊断类别 | 保存内容 |
| --- | --- |
| 请求与路线 | 尝试顺序、重定向、备用来源及实际 HTTP 状态。 |
| 格式与长度 | 声明类型、文件特征、各阶段长度及截断范围。 |
| 时间 | 排队、HTTP、备用、渲染和提取的阶段时刻及耗时。 |
| 生命周期 | 取消目标、等待任务、观察器、队列和实例的创建及释放。 |
| 资源 | 共同占用、限额及代表性 App/WebContent 测量。 |

诊断有大小和保留期限限制，并遵守凭据脱敏规则。
超时、来源替换和未读取范围仍须在模型结果中准确说明。
模型判断所需的限制不能只留在诊断中。

## 最终输出检查

应用先限制正文片段，再编码完整 JSON。
通用工具处理不能直接截取 JSON 字符串，或在字符串外追加警告。
需要提示限制时，应用更新 `limitations` 后重新编码。
文件转存也必须保留可解析的结果、来源和实际可用的续读信息。
转存后的 JSON 保留来源、限制和资源信息，正文为空，并通过 `offloaded_result_file` 指向完整原结果。
原正文编号和片段范围不再作为转存占位结果的有效续读承诺；文件写入失败时保留原结果。
无法保留全部元数据时，应用返回有效的失败对象并说明限制。

验证必须检查最终 Provider 请求中的工具结果。
提取器内部对象正确，不能代替最终模型输入正确。
详细步骤由 [G06 结果契约组](groups.json) 和 [iOS 专项步骤](ios-acceptance.md#模型结果与诊断分离)执行。
