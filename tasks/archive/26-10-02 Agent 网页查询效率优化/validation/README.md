原31项自检通过，只说明测试输入符合预期。
iOS 工具、真实 Agent 及真机行为均尚未验收。

## 初版范围与判定

第一版直接提取公开 HTML、纯文本及 Markdown。

| 输入 | 第一版通过条件 |
| --- | --- |
| PDF、PNG 或 JPEG | 工具识别资源，返回可定位地址，并说明内容尚未读取。 |
| HTTP 401 | 工具说明需要认证。 |
| HTTP 403 | 工具说明访问拒绝。 |
| HTTP 200 登录表单 | 工具说明登录限制，不作为目标正文返回。 |
| 跳转到登录页或受限页面 | 工具记录实际来源和限制。 |
| 公开内容包含受限链接 | 工具分别说明公开证据及未取得内容。 |

本任务暂不实施 PDF 文字提取及扫描、图片 OCR。
PDF 文字与扫描件内容案例延期，当前只验收资源边界。
图片理解能力仍按原可选范围处理。
这些能力未启用时，准确报告未读取可以通过边界验收。
对应内容查询仍未完成。
返回资源后，还要验证文件或图像工具的实际交接。

认证测试只使用合成 Cookie 和私人标记。
匿名读取不复制共享浏览器凭据。
工具共存测试另外在 `browser_use` 中建立模拟登录。
需要该身份或交互后页面时，模型继续选择对应浏览器标签。

### 三层证据

| 层级 | 验证什么 | 需要什么证据 |
| --- | --- | --- |
| `fixture_selfcheck` | 路由、状态、格式、延迟及固定样本符合预期。 | 实际本地请求及格式库检查。 |
| `ios_product` | 真实工具的读取、隔离、取消、输出及释放。 | iOS 请求、存储、阶段及资源记录。 |
| `agent_e2e` | Agent 工具选择及最终回答有充分依据。 | 完整会话、模型可见结果和事实对应来源。 |

案例的 `classification` 保留必测或可选类别。
案例的 `execution_group` 指向[分组清单](groups.json)。
产品层按原输入变体检查；Agent 层使用关联的代表查询证据。
代表查询未实际覆盖某个限制时，不能把该限制标记为通过。
原模型层重复执行要求已按本轮确认改为分组取证。
网站自检不会自动将产品案例改为通过。
Python 请求、假工具或 HTTP 200 不能替代产品及 Agent 证据。

执行者按以下顺序安排：

1. 产品实现后，先执行读取、结果和内容组。
2. 产品测试逐项覆盖边界、隔离、生命周期和共存变体。
3. 真实 Agent 执行5类代表查询，使用正常提示及全部工具。
4. 混合批次检查真实调用配对，重载后继续正常查询。
5. 正确性和资源边界通过后，再执行同配置真机对照。

5类代表查询及其证据关联在 `groups.json` 的 `agent_queries` 中定义。
测试在相同模型、提示和配置下重复，记录实际重复次数。
同一轨迹可支持多项判据，但不能替代轨迹未覆盖的产品变体。
各组和各代表查询目前均为 `not_executed`。

## 生成样本与运行本地自检

### 生成和自检

当前机器的 bundled Python 包含 Pillow、ReportLab 和 pypdf。
系统 `python3` 缺少这些格式依赖。
在本目录执行以下命令：

```sh
PYTHON_FIXTURE=/Users/huyuanzhao/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3
"$PYTHON_FIXTURE" generate_fixtures.py
"$PYTHON_FIXTURE" verify_fixtures.py
```

生成器只写入旁边固定的 `fixtures/`，不接受任意输出目录。
运行时位置不同时，将等效解释器路径赋给 `PYTHON_FIXTURE`。

自检按以下步骤执行：

1. 脚本在 `127.0.0.1` 随机端口启动网站。
2. 脚本实际请求各固定路由。
3. 脚本用 pypdf 和 Pillow 检查返回的样本。
4. 脚本检查响应上限、连接上限及关闭行为。
5. 脚本关闭网站，并保存独立报告。

默认报告是 `/private/tmp/web-read-fixture-selfcheck.json`。
`--output PATH` 可以指定报告位置。
报告保留以下证据标记：

- `fixture_server_only`。
- `product_acceptance: not_tested`。
- `agent_end_to_end: not_tested`。

### 单独启动测试网站

```sh
python3 fixture_server.py
```

网站打印随机端口和本地地址。

| 配置 | 默认上限 |
| --- | --- |
| 监听地址 | 仅 loopback，允许 localhost 或回环 IP。 |
| 并发请求 | 8个。 |
| 单响应 | 1 MiB。 |
| 已接受连接的读写 | 2秒超时。 |
| 路由延迟 | 最长5秒。 |

路径只能选择固定路由，不能读取任意磁盘文件。
网站不读取生产 Cookie、RPC 缓存或真实账号。
网站不记录网址、Cookie、请求头或响应体。

关闭按以下顺序执行：

1. 网站停止接受连接。
2. 网站关闭活跃 socket。
3. 网站在有时限的等待内结束处理线程。

原自检占满8个空闲或未完成请求头的连接。
第9个请求返回503，关闭后活跃请求和连接均归零。

### 响应上限输入

产品预算从被测构建或显式测试配置取得。

| 输入 | 用途与限制 |
| --- | --- |
| `/pdf/large`，约606 KiB、32页 | 测试真实 PDF 响应预算。 |
| `/large?bytes=768000` | 测试产品在真实768000字节响应上的上限。 |
| `/large?bytes=2000000` | 网站返回小型413，只证明网站自身限制。 |
| 流式路由 | 按网站配置上限缩短响应。 |
| 自检配置1 KiB上限 | 核对流式响应不会超过网站上限。 |

超限样本必须实际大于产品的配置值。
测试可以降低产品预算，但需要记录覆盖配置。
现有样本不足时补充受控样本。
网站413不能替代产品限额验证。

### 长文输入

`/long/html` 含400个英文段落、表格和代码。
原自检解析文本内容，核对单元格及代码。
`END-READ-MARKER-90631` 的文本偏移为53,351，超过30,000字符。
HTML 将标识符拆在多个元素中，测试提取后的重建结果。

页面明确链接同源公开 Markdown 摘录。
摘录保留对应表格和代码，但不能代表完整长文。
网站也支持 HTTP Range，自检核对206尾部响应。
这些检查不证明最终模型输入完整，产品层仍需核对。

## iOS 与 Agent 验收

测试通过待验收构建的真实工具入口执行。

| 检查对象 | 保存证据 |
| --- | --- |
| 请求 | 请求和最终网址、状态、格式及实际字节数。 |
| 正文 | 提取状态、长度、截断范围及取消原因。 |
| 生命周期 | 阶段时间、请求、观察器、队列及实例释放。 |
| 身份 | iOS 请求与网站存储的隔离。 |
| 输出 | 最终模型实际收到的完整工具结果。 |
| 回答 | 来源、调用次数及逐条事实核对。 |

固定标记可以证明目标位置，不能独立证明理解或事实关系。
图片查询要核对数据与具体图片，表格查询要核对行列关系。
边界识别通过不等于内容回答成功。
准确报告限制时，不要求额外调用模型来补充成功记录。
本轮没有执行付费模型实验。

8项共存验收只在产品或真实 Agent 层执行。
原31项自检不能证明工具选择、接管、共同预算或结果配对。
总截止时间、各阶段停止及共存步骤见[专项说明](ios-acceptance.md)。

### Simulator 与真机连接

| 环境 | 测试连接条件 |
| --- | --- |
| Simulator | 先确认应用可以访问宿主机 loopback。 |
| 实体 iPhone | 另行安排符合安全边界的连接，或使用受控公开页面。 |

实体 iPhone 不能直接访问 Mac 的 `127.0.0.1`。
测试网站保持回环监听，不改为局域网或外网服务。
真机锁屏结论单独记录，Simulator 结果不能替代。
