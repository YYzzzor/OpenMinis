## 官方设计可以支持哪些选择

| 资料 | 已公开的设计 | 本任务参考的内容 |
| --- | --- | --- |
| [Anthropic web fetch](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool) | 独立读取已知网址；返回文档、网址、抓取时间或错误。 | 正文与来源分别表示，读取上限和失败可观察。 |
| [OpenAI web search](https://developers.openai.com/api/docs/guides/tools-web-search) | 支持搜索、打开页面和页内查找，并保留调用及来源引用。 | 来源发现、页面定位和回答引用分别承担职责。 |
| [Google URL Context](https://ai.google.dev/gemini-api/docs/url-context) | 网址上下文可与搜索组合；结果包含来源引用及读取尝试元数据。 | 区分回答依据与读取诊断。 |
| [OpenAI Function Calling](https://developers.openai.com/api/docs/guides/function-calling#formatting-results) | 开发者可以把 JSON、错误码或文字作为工具结果字符串。 | JSON 序列化后沿用现有 Provider 包装，并对应原调用。 |

多个公开工具区分正文、来源和状态，但没有统一网页结果标准。
这些资料不能证明所有 Agent 都把每个诊断字段送入模型。
Google 返回的读取元数据也不能直接视为公开的完整模型上下文。
OpenAI 公开的调用和引用结构不等于公开全部内部页面返回。

Anthropic 网页抓取不执行网页 JavaScript。
其 dynamic filtering 用于过滤已取得的内容，不等于动态渲染。
官方托管工具的协议外层也不能直接复制为 iOS 本地自定义工具。

因此，本任务依据官方先例确定职责划分，再制定自己的小型 JSON。
匿名 WebKit、正文编号及共同资源管理仍须由 iOS 产品验证。

## 已确认的结果组织

模型收到以下内容：

- 工具返回 Markdown 正文。
- 工具返回来源、标题和抓取时间。
- 工具返回读取状态及影响回答的限制。
- 工具返回实际可用的正文编号和续读范围。
- 工具返回与目标相关的未读取资源信息。

程序在一次调用内完成有上限的机械回退，不逐阶段额外调用模型。
模型取得结果后，再判断证据是否足够。
完整字段及示例见[结果契约](../validation/result-contract.md)。

详细阶段耗时、资源计数和内部请求时序保留在诊断中。
诊断可关联原工具调用，并遵守有界保留及脱敏规则。
超时、来源替换和内容缺口仍须出现在模型结果中。

MinisX 当前工具结果使用字符串，由 Provider 包装协议外层。
本版将 JSON 编码为该字符串，不新增一种 Provider 外层协议。
最终输出必须验证通用截断和文件转存没有破坏 JSON 或续读信息。

## 当前能力范围

本任务不增加 PDF 文字提取、扫描 PDF OCR 或图片 OCR。
PDF 保留类型识别、资源地址和未读取状态。
原内容样本保留，供后续任务使用。
图片理解和 `web_read` 登录能力仍保持待决定。

## 已确认的分组执行

案例库保留66个场景，不要求逐项执行完整模型查询。
[groups.json](../validation/groups.json)将当前验收组织为20个主要组。

| 执行方式 | 覆盖范围 |
| --- | --- |
| 参数化产品测试 | 覆盖42个新增必测案例、关键变体及 JSON 契约。 |
| 5类真实 Agent 查询 | 验证工具选择、续读、事实依据及资源交接。 |
| 混合批次及重载 | 验证原调用配对和后续 Agent 正常继续。 |
| 真机代表查询对照 | 验证同配置前台与锁屏，以及实际资源表现。 |
| 可选能力案例 | 6个新增案例暂不执行，不作为本版通过条件。 |

历史18个案例仅作为研究和输入参考，不沿用旧结果判定新工具通过。
其中历史 PDF 文字查询归入延期能力，不实施其旧文字提取要求。
同一份完整证据可以关联多个判据，但只证明实际观察的变体。
阶段停止、匿名路线、身份作用域和资源创建顺序仍逐项检查。
